# BTServer / Packet Sniffer Notes

The native app includes an app-level packet trace:

- BLE advertisements accepted as Garmin candidates.
- Every CoreBluetooth GATT write to the Garmin TX characteristic.
- Every notification from the Garmin RX characteristic.
- Every decoded GFDI packet before COBS/after COBS.

That is enough to inspect Garmin ML, MLR, COBS, GFDI, file-transfer status, pacing, and retransmission behavior for traffic generated by this app.

It is not a raw over-the-air RF sniffer. iOS does not expose that through CoreBluetooth.

The iPhone 5 root snapshot shows two useful private clues:

- `com.apple.bluetooth.BTPacketLogger`
- `com.apple.MobileBluetooth.logging.hci`

Those suggest a deeper BTServer/HCI capture path exists on iOS 10, but it needs a separate private-client experiment. The next concrete step is to write a small tool/tweak that tries to attach to the BTPacketLogger Mach service and records HCI ACL/LE events. Until that works, use the native app trace for Garmin protocol bytes and an external sniffer for true RF/link-layer captures.
